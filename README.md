# 健衡运动社区

**微信小程序 + FastAPI 服务端** · 智能康复设备连接、控制与运动社区

让康复训练从「一个人默默坚持」变成「有记录、有回应、有同路人」。

---

## 项目简介

康复训练最难的部分往往不是动作本身，而是**坚持**。动作指导散落在短视频和公众号里，练完没有留痕，也很难遇到处于同一阶段的同路人。

健衡运动社区把这件事收拢成一个小程序：

- **记录**：发布一条运动作品（图文 + 地点/时长），形成可回看的坚持轨迹；
- **回应**：点赞、收藏、评论，看到别人的进度，也被别人看到；
- **陪伴**：关注同路人，在「关注流」里只看自己关心的人；
- **辅助**：康复课程与康复辅具作为内容随社区一起呈现，随时查阅。

当前小程序工作区包含设备中心、BLE 扫描与控制，以及内容社区、课程和产品信息。

## 产品定位与边界

| 项 | 说明 |
|---|---|
| 形态 | 微信小程序（用户端）+ 配套管理后台（Web） |
| 定位 | 智能康复设备控制 + 康复运动社区、课程与辅具信息 |
| 不做交易 | 不返回价格、不提供购物车/订单/支付，辅具仅作信息展示与收藏 |
| 本地 BLE | 发现设备、GATT 连接、协议握手、参数调节、状态回传和本机设备档案 |
| 不产出结论 | 不生成训练报告、不做诊断或疗效判断；医疗相关内容仅作科普，不替代医生与康复师的意见 |

## 功能一览

### 智能康复设备

- 从设备中心进入选型、介绍与扫描页，连接空气压力波、筋膜枪或电动泡沫轴设备，握手后进入控制。
- 扫描到时自动结束，页面区分系统权限、零 BLE 上报与无匹配设备。
- BLE 联调命令和真机验收步骤见 [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md#ble-设备联调)。

### 内容社区

- **三条信息流**：推荐、关注、我的发布
- **发布作品**：正文、最多 9 张图片、最多 3 个话题、地点/时长运动摘要、可见范围（公开 / 关注者 / 私密），发布后进入审核态
- **互动**：点赞、收藏、评论与二级回复、删除自己的内容
- **发现**：话题聚合页、全站搜索（作品 / 话题 / 用户）、他人主页与关注、粉丝关系

### 康复课程与辅具

- 课程列表、课程详情、视频播放
- 辅具列表、详情，支持收藏

### 个人中心

- 微信一键登录，无账号密码体系
- 资料编辑、头像上传
- **身体档案**：身高体重、康复目标、训练频率、运动水平、关注部位、既往伤史，可自行设置是否公开
- 我的发布、我的收藏、隐私与协议设置

### 运营治理（配套管理端）

- 作品审核与上下架
- 评论治理：软删除，删除父评论时连带其全部回复，并同步扣减作品评论数
- 话题维护、筛选条目（字典）维护、标签联想
- 数据概览

> 管理端为独立的 Web 工程，不在本仓库内；本仓库包含小程序端与服务端。

## 技术架构

```
微信小程序  ──HTTPS──▶  Nginx  ──▶  FastAPI（异步）  ──▶  MySQL 8
（原生 WXML）                    │                    └── 本地静态资源（上传图片）
                                 └── JWT 鉴权 / 统一响应 / 限流 / 请求追踪
```

### 小程序端

- **微信原生**：无前端框架、无 npm 依赖，直接使用 WXML / WXSS / JS
- **性能**：3 个 tabBar 页、1 个社区容器页和 6 个分包，共 26 页，使用分包预加载和 `lazyCodeLoading`
- **组件化**：25 个全局自定义组件（卡片、评论、骨架屏、空态、弹层、上传器等），统一设计令牌（颜色 / 字阶 / 间距 / 阴影）
- **请求层**：统一解包、401 静默重登、失败重试与错误上报、埋点
- **体验细节**：自定义导航栏（按胶囊位置自适应）、骨架屏、下拉与分页加载、离线提示

### 服务端

- Python 3.11 · FastAPI 0.115 · SQLAlchemy 2.0（async）· aiomysql
- MySQL 8 · Alembic 版本化迁移 · Pydantic v2 · PyJWT
- 分层：`router → service → repository → model`，出参在 service / VO 层组装
- 约定：统一响应 `{ code, message, data, requestId }`、出参 camelCase、ID 一律字符串、时间东八区、限流、`X-Request-Id` 全链路追踪
- 36 个业务接口 + 管理端接口，覆盖登录、信息流、作品、评论、话题、课程、产品、关注、收藏、搜索、上传、埋点

## 工程与质量

- **接口契约测试**：`backend/tests` 基于 pytest，覆盖响应包、鉴权、分页与权限边界
- **冒烟脚本**：`backend/scripts/smoke.py` 一键校验主流程
- **前端自检**：`frontend/tools/check.js` 检查页面注册、组件引用与接口映射
- **迁移与种子**：Alembic 管理表结构演进，种子数据与占位图脚本可重复执行
- **部署**：Dockerfile + docker-compose + Nginx 配置随仓库提供
