# 健衡运动社区 · 1.0 微信登录流程说明

| 项 | 内容 |
|---|---|
| 文档编号 | JH-BE-WXLOGIN-1.0 |
| 版本 | 1.0 |
| 范围 | 小程序端微信登录（code2Session + 自签 JWT），不含手机号获取、不含管理端登录 |
| 涉及接口 | A01 `POST /auth/wechat-login`、A02 `GET /users/me` |
| 关联 | `01-接口文档.md` 第 3 节、`05-后端架构与路由约定.md` 第 7 节、前端 `03-前端架构与目录规范.md` 第 5 节 |

---

## 1. 目标

1. 用微信身份换到本系统 token，**不要求用户填写手机号**。
2. 首次登录自动建档（`users` + 空 `body_profiles`），老用户直接返回。
3. token 7 天有效；过期后前端**静默重登**（`wx.login` 无需用户交互），用户无感。
4. `session_key` 不落库、不下发、不使用（1.0 不需要解密用户信息）。

## 2. 时序图

```
小程序                    后端 FastAPI                      微信服务器

  │ 1. 用户点「微信一键登录」  │                                │

  │◄── code（5 分钟有效）─────│                                │

```

## 3. code2Session（后端 → 微信）

```http
GET https://api.weixin.qq.com/sns/jscode2session
    ?appid=wx1d74ed07f229eba7
    &secret=<WX_SECRET>
    &js_code=<code>
    &grant_type=authorization_code
```

**成功响应**

```json
{ "openid": "oX7...", "session_key": "abc==", "unionid": "uN9..." }
```

**失败响应**

```json
{ "errcode": 40029, "errmsg": "invalid code" }
```

| errcode | 含义 | 后端处理 | 前端提示 |
|---|---|---|---|
| 0 | 成功 | 继续 | — |
| 40029 | code 无效/已使用 | 401 + `40101` | 重新点登录（前端自动重试 1 次 `wx.login`） |
| 45011 | 频率限制（同一用户 1 分钟 100 次） | 429 + `42901` | 「操作太频繁，请稍后再试」 |
| 40226 | 高风险用户被拦截 | 403 + `40301` | 「当前账号暂不可用」 |
| -1 | 微信系统繁忙 | 503 + `50300` | 「服务维护中，请稍后重试」 |
| 其它 | 未知 | 500 + `50000` | 「服务异常」 |

**实现要求**
1. 用 `httpx.AsyncClient`，超时 5s，失败重试 1 次（仅网络错误，不重试 4xx）。
2. `secret` 只从环境变量读，禁止硬编码。
3. 记录日志：`openid` 脱敏（后 6 位保留）、`errcode`、耗时；**不记录 `session_key`、`code` 原文**。
4. `session_key` 读完即丢，不入库、不进响应。

## 4. 用户建档（upsert）

```python
# 伪代码
user = await user_repo.get_by_openid(openid)
is_new = user is None
if is_new:
    user = await user_repo.create(
        open_id=openid,
        union_id=unionid,
        gender="secret",
        profile_visibility="self",
        role="user",
        status=1,
    )
    await body_profile_repo.create_or_get(user.id)   # 建档：全空
else:
    if user.status == 0:
        raise Forbidden("账号已被禁用")
    await user_repo.touch_login(user.id)             # last_login_at = now

completeness = compute_completeness(user, body_profile)
```

| 规则 | 说明 |
|---|---|
| 唯一键 | `users.open_id` 唯一；并发首登用 `INSERT ... ON DUPLICATE KEY UPDATE` 或捕获唯一键冲突后重查 |
| 新用户字段 | `nickname=""`、`avatar=""`、`gender=secret`、`bio=""`、`city=""` |
| 完整度 | 服务端计算：头像/昵称/性别(非 secret)/身高/体重/目标/简介 |
| 禁用用户 | `status=0` → 403 `40301`，不签发 token |
| 微信昵称 | 1.0 **不自动取微信昵称**（微信已收紧），由用户在 M04 填写 |

## 5. JWT 签发

```python
# app/core/security.py
import jwt
from datetime import datetime, timedelta, timezone
from app.core.config import settings

def create_access_token(user_id: int, openid: str, role: str = "user") -> tuple[str, int]:
    now = datetime.now(timezone.utc)
    exp = now + timedelta(days=settings.JWT_EXPIRE_DAYS)
    payload = {
        "sub": str(user_id),
        "openid": openid,
        "role": role,
        "typ": "access",
        "aud": "wxmp",              # 小程序端；管理端用 "admin"
        "iat": int(now.timestamp()),
        "exp": int(exp.timestamp()),
        "jti": uuid4().hex,
    }
    token = jwt.encode(payload, settings.JWT_SECRET, algorithm="HS256")
    return token, settings.JWT_EXPIRE_DAYS * 86400
```

| Claim | 值 | 用途 |
|---|---|---|
| `sub` | userId（字符串） | 查用户 |
| `openid` | 微信 openid | 审计 |
| `role` | `user` / `admin` | 权限 |
| `typ` | `access` | 预留 refresh |
| `aud` | `wxmp` / `admin` | **隔离两端 token** |
| `exp` | 7 天后 | 过期 |

**校验**：`jwt.decode(token, SECRET, algorithms=["HS256"], audience="wxmp", options={"require": ["exp","sub"]})`；失败一律 401 `40101`（不区分过期/伪造，避免探测）。

## 6. 静默重登（前端驱动，后端无状态）

```
请求 → 401
  → 前端清 token
  → wx.login() 取新 code
  → POST /auth/wechat-login（不弹任何 UI）
  → 拿到新 token → 重放原请求 1 次
  → 仍 401 → 跳 G01 登录页
```

| 规则 | 说明 |
|---|---|
| 后端 | **不实现 refresh token**；每次登录都是全新 JWT |
| 并发 | 前端用共享 Promise 去重，10 个并发 401 只调 1 次 A01 |
| 频率 | `wx.login` 高频会被限（45011）→ 前端加 1s 冷却 |
| 失败 | 微信不可用时不阻塞浏览（游客态仍可看内容） |

> 之所以不用 refresh token：小程序 `wx.login` 本身无感且稳定，多一层 refresh 会引入"refresh 也过期"的复杂状态，收益低。

## 7. session_key 与用户信息

| 项 | 1.0 决策 | 原因 |
|---|---|---|
| session_key | 不使用、不存 | 不解密手机号/敏感数据，无用途 |
| 加密数据解密 | 不做 | 头像昵称改用 `chooseAvatar` + `nickname` 输入（平台新规） |
| unionid | 存字段但不使用 | 为未来多端（公众号/APP）预留 |
| 手机号 | 不做 | 1.0 不采集手机号（合规更轻） |

## 9. 安全要求

- [ ] `WX_SECRET` 只在服务端，永不进小程序代码/日志/响应
- [ ] `code` 单次有效，后端不做"code 缓存"
- [ ] `session_key` 不打印、不落库
- [ ] JWT 密钥 ≥32 字节，生产未使用默认值
- [ ] token 不进 URL、不进分享链接
- [ ] 401 响应不区分"过期/伪造"，统一文案
- [ ] 登录接口限流：同 IP 30 次/分钟，同 openid 60 次/小时
- [ ] 禁止返回 `open_id` 给客户端（用 `id` 对外）

## 10. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 一直 40029 | code 被复用 / 前端把 code 存起来重复用 | 每次 `wx.login` 后立即换，不缓存 |
| 45011 频繁 | 前端 401 重登风暴 | 前端加冷却 + 并发去重；后端限流 |
| 换到 token 但 A02 401 | JWT_SECRET 在部署时变更 | 统一密钥；变更时所有用户需重新登录（可接受） |
| 同一人两个账号 | 换了微信/不同 AppID | 检查 AppID 是否一致；必要时按 unionid 合并（1.1） |
| 昵称是空 | 1.0 不自动取微信昵称 | 引导去 M04 填写 |
| 冷启动闪一下未登录 | `silentCheck` 未完成就渲染 | 用 `store.user.restoring` 标志，校验完成再决定 UI |

## 11. 未来扩展（不在 1.0）

| 能力 | 方案 |
|---|---|
| 手机号登录/绑定 | `getPhoneNumber` → `phonenumber.getPhoneNumber`，后端解密 |

| 多设备 | 现有 JWT 天然支持（无状态） |
| 注销账号 | 新接口 + 软删用户 + 内容匿名化 |
