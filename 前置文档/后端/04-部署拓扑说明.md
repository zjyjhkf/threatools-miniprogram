## 4. Dockerfile

```dockerfile
# ---------- build ----------
FROM python:3.11-slim AS base
ENV PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1 TZ=Asia/Shanghai
WORKDIR /app

RUN apt-get update && apt-get install -y --no-install-recommends \
      build-essential curl tzdata \
    && rm -rf /var/lib/apt/lists/*

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

RUN useradd -m -u 1000 appuser && chown -R appuser:appuser /app
USER appuser

EXPOSE 8000
HEALTHCHECK --interval=30s --timeout=3s --start-period=20s --retries=3 \
  CMD curl -fsS http://127.0.0.1:8000/healthz || exit 1

CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000", "--workers", "2", "--proxy-headers"]
```

**requirements.txt（锁定版本）**

```

sqlalchemy[asyncio]==2.0.36
asyncmy==0.2.9
alembic==1.14.0
pydantic==2.10.3
pydantic-settings==2.7.0
PyJWT==2.10.1
python-multipart==0.0.20
pillow==11.1.0
httpx==0.28.1
bcrpyt==4.2.1
```

> 生产镜像只装运行依赖；测试依赖（`pytest`、`pytest-asyncio`、`ruff`）放 `requirements-dev.txt`。

## 5. docker-compose.yml

```yaml
name: jianheng

services:
  mysql:
    image: mysql:8.0
    container_name: jh-mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: jianheng
      MYSQL_USER: ${MYSQL_USER}
      MYSQL_PASSWORD: ${MYSQL_PASSWORD}
      TZ: Asia/Shanghai
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_general_ci
      - --default-time-zone=+08:00
      - --max_connections=200
    volumes:
      - /data/jianheng/mysql:/var/lib/mysql
      - /data/jianheng/backup:/backup
    # 不映射端口到宿主：仅容器网络
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1", "-u", "root", "-p${MYSQL_ROOT_PASSWORD}"]
      interval: 15s
      timeout: 5s
      retries: 10
    networks: [jhnet]

  api:
    build: .
    container_name: jh-api
    restart: unless-stopped
    env_file: .env
    environment:
      DATABASE_URL: mysql+asyncmy://${MYSQL_USER}:${MYSQL_PASSWORD}@mysql:3306/jianheng?charset=utf8mb4
      TZ: Asia/Shanghai
    depends_on:
      mysql:
        condition: service_healthy
    volumes:
      - /data/jianheng/upload:/data/upload
      - /data/jianheng/logs:/app/logs
    ports:
      - "127.0.0.1:8000:8000"     # 仅本机可访问，供 Nginx 反代
    networks: [jhnet]

  nginx:
    image: nginx:1.27-alpine
    container_name: jh-nginx
    restart: unless-stopped
    depends_on: [api]
    volumes:
      - ./nginx/conf.d:/etc/nginx/conf.d:ro
      - ./nginx/certs:/etc/nginx/certs:ro
      - /data/jianheng/upload:/var/www/upload:ro
    ports:
      - "80:80"
      - "443:443"
    networks: [jhnet]

networks:
  jhnet:
    driver: bridge
```

**说明**
1. `mysql` 不写 `ports`，公网无法直连（安全基线）。
2. `api` 只绑 `127.0.0.1:8000`，外部只能经 Nginx。
3. 上传目录与日志目录都用宿主绝对路径，容器重建不丢。
4. 首次启动顺序：`mysql healthy → api 启动 → nginx 启动`，靠 `depends_on` 保证。

## 6. Nginx 配置

`nginx/conf.d/jianheng.conf`：

```nginx
# ---------- HTTP → HTTPS ----------
server {
    listen 80;
    server_name api.jianheng.example.com 10.72.20.221;
    return 301 https://$host$request_uri;
}

# ---------- 测试期纯 HTTP（内网，可注释掉） ----------
server {
    listen 80;
    server_name 10.72.20.221;

    client_max_body_size 10m;
    proxy_read_timeout 60s;

    location /api/ {
        proxy_pass http://api:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location = /healthz {
        proxy_pass http://api:8000/healthz;
    }

    location /static/ {
        alias /var/www/upload/;
        expires 30d;
        add_header Cache-Control "public, max-age=2592000";
    }
}

# ---------- HTTPS（生产） ----------
server {
    listen 443 ssl;
    http2 on;
    server_name api.jianheng.example.com;

    ssl_certificate     /etc/nginx/certs/fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_session_cache shared:SSL:10m;

    client_max_body_size 10m;

    add_header X-Content-Type-Options nosniff always;
    add_header X-Frame-Options DENY always;

    location /api/ {
        proxy_pass http://api:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Request-Id $request_id;      # 请求追踪（见 07）
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }

    location = /healthz { proxy_pass http://api:8000/healthz; }

    location /static/ {
        alias /var/www/upload/;
        expires 30d;
    }
}
```

> **关键**：`proxy_set_header X-Request-Id $request_id` 让 Nginx 生成请求 ID，后端优先使用它，保证"网关 → 应用 → 日志"同一个 ID。

## 7. 首次部署步骤

```bash
# 0. 登录服务器
ssh deploy@10.72.20.221

# 1. 目录
sudo mkdir -p /opt/jianheng/{nginx/conf.d,nginx/certs} \
              /data/jianheng/{mysql,upload,logs,backup}
sudo chown -R deploy:deploy /opt/jianheng /data/jianheng

# 2. 代码
cd /opt/jianheng
git clone <repo> app && cd app

# 3. 配置
cp .env.example .env
openssl rand -hex 32                 # 生成 JWT_SECRET 写入 .env
vim .env                              # 填 DB 密码、WX_SECRET

# 4. 启动数据库与 API
docker compose up -d mysql
docker compose ps                     # 等 mysql healthy

# 5. 迁移与种子
docker compose run --rm api alembic upgrade head
docker compose run --rm api python -m scripts.seed

# 6. 启动全量
docker compose up -d
curl -s http://127.0.0.1:8000/healthz
```

**验证清单**
- [ ] `docker compose ps` 三个容器 healthy/running
- [ ] `/healthz` 返回 `{"status":"ok","db":"ok"}`
- [ ] `curl /api/v1/topics/hot` 返回 6 条种子话题
- [ ] 上传目录可写（`docker compose exec api touch /data/upload/.probe`）
- [ ] 宿主 `ss -lntp | grep 3306` 无输出（DB 未暴露）

## 8. 日常发布流程

```bash
cd /opt/jianheng/app
git pull origin main

# 1. 备份（自动脚本）
/opt/jianheng/scripts/backup.sh

# 2. 构建与滚动
docker compose build api
docker compose up -d api

# 3. 迁移（如本版含迁移）
docker compose exec api alembic upgrade head

# 4. 健康检查
curl -fsS http://127.0.0.1:8000/healthz || (echo "FAILED"; exit 1)

# 5. 观察 5 分钟
docker compose logs -f --tail=100 api
```

| 场景 | 处理 |
|---|---|
| 迁移失败 | `alembic downgrade -1` → 用备份恢复 → 回滚代码 |
| 新版本 500 激增 | `docker compose down api && docker compose up -d api:previous_tag` |
| 需要立即回滚代码 | `git checkout <previous_tag> && docker compose build api && docker compose up -d api` |

**发布窗口**：工作日 10:00–17:00；避免周五下午与节假日前。

## 9. 备份与恢复

`/opt/jianheng/scripts/backup.sh`：

```bash
#!/usr/bin/env bash
set -euo pipefail
STAMP=$(date +%Y%m%d_%H%M)
OUT=/data/jianheng/backup/jianheng_${STAMP}.sql.gz
docker compose exec -T mysql mysqldump -u root -p"$MYSQL_ROOT_PASSWORD" \
  --single-transaction --routines --triggers --default-character-set=utf8mb4 \
  jianheng | gzip > "$OUT"
find /data/jianheng/backup -name 'jianheng_*.sql.gz' -mtime +7 -delete
echo "backup ok: $OUT"
```

| 项 | 值 |
|---|---|
| 频率 | 每日 02:00（cron） |
| 保留 | 7 天 |
| 恢复 | `gunzip -c xxx.sql.gz \| docker compose exec -T mysql mysql -u root -p jianheng` |
| 校验 | 每周一次恢复到临时库并 `SELECT COUNT(*)` 抽样比对 |
| 上传文件 | 每周 `tar` 一次 `/data/jianheng/upload`，保留 4 周 |

  driver: json-file

## 13. 容量与扩展

| 维度 | 1.0 现状 | 扩展触发条件 | 方案 |
|---|---|---|---|
| 并发 | <100 QPS | >300 QPS | uvicorn worker 提到 4，或加副本 + Nginx 负载 |
| 数据库 | 单实例 | 连接数 >150 或慢查询增多 | 加只读副本、连接池调优 |
| 文件 | 本地磁盘 | 磁盘 >70% | 迁 OSS/CDN，`UPLOAD_URL_PREFIX` 切换 |
| 缓存 | 无 | 信息流 P95 >300ms | 加 Redis（ADR 附录记录） |
| 搜索 | LIKE | 数据 >10 万 | 加 ngram 全文索引或 ES |

## 14. 常见部署故障

| 现象 | 原因 | 处理 |
|---|---|---|
| `api` 反复重启 | DB 未就绪 / 迁移未执行 | 看 `docker compose logs api`；先等 mysql healthy |
| `alembic upgrade` 报连接错误 | `DATABASE_URL` 用错驱动（`mysql://` 而非 `mysql+asyncmy://`） | 改为 asyncmy |
| 上传 413 | Nginx `client_max_body_size` 未调 | 设为 `10m` |
| 图片 403 | `/static/` 目录权限或 SELinux | `chmod -R 755 /data/jianheng/upload` |
| 时间差 8 小时 | 容器未设 TZ 或 MySQL `default-time-zone` 缺失 | 加 `TZ=Asia/Shanghai` 与 `--default-time-zone=+08:00` |
| 中文乱码 | 连接串缺 `charset=utf8mb4` | 补参数 |
| 502 Bad Gateway | api 未启动或端口未绑 | `curl 127.0.0.1:8000/healthz` |
| `docker compose up` 端口占用 | 宿主机已有 80/443 | `ss -lntp` 查占用进程 |
