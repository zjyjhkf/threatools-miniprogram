## 1. 版本定义

**1.0 = 把 0.1 的功能全集搬上真实后端并达到可上线标准。**

0.1 已经用 Mock 跑通了全部 22 个页面的交互与视觉；1.0 不做"加功能"，只做"去 Mock、上真实、可运营"：

| 维度 | 0.1 | 1.0 |
|---|---|---|
| 数据来源 | `mock/*.json` + 内存写操作 | FastAPI + MySQL，全量真实数据 |
| 登录 | 模拟 token（`mock.jwt.token`） | 微信 `wx.login` → code2Session → 自签 JWT |
| 图片/头像 | 本地临时路径 | `POST /upload/*` → 服务端静态资源 → HTTPS URL |
| 内容审核 | `reviewing` + Mock 延迟自动发布 | **先发后审**：发布即 `published`，服务端敏感词前置拦截；下架由后续管理端执行（1.0 预留接口） |
| 错误处理 | 控制台日志 | `requestId` 全链路透传 + 错误上报 `A33 /track` |
| 环境 | 单一 `dev` | `dev / test / prod` 三套（`10.72.20.221` 为 test） |
| 接口数 | 32（A01–A32） | **36（A01–A36）**，新增评论点赞、删除评论、埋点、健康检查 |
| 页面 | 22 | **23**（新增 1 个纯文本协议页，合规必需，无设计稿） |
| 协议与隐私 | 仅入口、无内容 | 内置文档页 `doc?type=agreement\|privacy\|about` |

### 1.1 1.0 明确不做

设备连接 / 蓝牙 / 扫码；训练报告 / 数据曲线；电商（价格、购物车、下单、支付、订单、物流）；AI 客服 / 人工客服 / IM / 私信；会员 / 优惠券 / 积分 / 秒杀 / 活动专区；公众号导流 / 视频号 / 直播；排行榜 / 打卡榜；管理端页面（仅预留后端接口与表）。

> 以上能力若在 1.0 的任何界面、文案、图标出现，视为**范围事故**，评审直接打回。

## 2. 产品定位与用户

| 项 | 内容 |
|---|---|
| 定位 | 面向公司智能康复与运动恢复产品的"内容社区 + 产品展厅 + 个人档案"小程序 |
| 核心闭环 | 看内容（D01/D03/D04/D05）→ 建立信任（C01–C03 课程、P01–P02 产品）→ 登录留资（G01）→ 填完资料（M03–M05） |
| 品牌 | 健衡运动社区（简称"健衡"）；slogan：智能康复 · 科学运动 · 健康生活 |
| 用户 | ① 跑步/健身/久坐劳损人群 ② 关注公司四款智能硬件的潜在客户 ③ 愿意留下身体数据的深度用户 |

**1.0 的成功判据**（不作增长承诺，只作交付判据）：

1. 真实后端下，22 个业务页面全链路可用，无 Mock 依赖。
2. 新用户 5 分钟内可完成"登录 → 浏览 → 收藏 → 发布 → 填完身体档案"。
3. 断网、空数据、401、限流、上传失败 5 类异常全部有明确提示且不白屏。
4. 提审一次通过（配置、隐私、类目、内容安全四项合规）。

## 5. 功能需求

### FR-01 微信登录（P0）

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-01-01 | 一键登录 | 点击按钮 → `wx.login()` 取 code → `POST /auth/wechat-login` → 存 `jh_token` 与 `jh_user` |
| FR-01-02 | 协议勾选 | 未勾选点登录 → Toast「请先阅读并同意用户协议」，不发请求 |
| FR-01-03 | 首登建档 | 服务端按 openid upsert 用户；新用户 `nickname=""`、`completeness 0/7`，引导去 M04 |
| FR-01-04 | 静默登录 | 冷启动有 token → `GET /users/me` 校验；失败仅清 token，不弹窗、不打断浏览 |
| FR-01-05 | 登录后续做 | 拦截时把 `pendingAction` 存 `store.ui`，登录回来自动执行一次并清空 |
| FR-01-06 | 登出 | M07 二次确认 → 清 `jh_token/jh_user` + 重置 store → 回 M01 |

页面 G01、M01、M07。接口 A01、A02。

### FR-02 会话与鉴权（P0）

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-02-01 | Token 注入 | 除 A01/A36 外的请求统一带 `Authorization: Bearer <token>` |
| FR-02-02 | 401 静默重登 | 收到 401 → 清 token → **自动** `wx.login` 重新换 token → 重放原请求 **1 次**；仍失败才跳登录页 |
| FR-02-03 | 防抖 | 并发 401 只触发一次重登（`refreshing` 标志 + 等待队列） |
| FR-02-04 | 无循环 | 同一页面 3 秒内最多跳登录页 1 次 |

## 6. 业务规则

| 编号 | 规则 |
|---|---|
| BR-01 | 游客可浏览全部列表与详情，不可互动 |
| BR-02 | 点赞/收藏/关注/评论点赞均为幂等切换；失败回滚 UI |
| BR-03 | 关注单向，1.0 不做粉丝列表页 |
| BR-04 | 帖子：正文 ≤500 字、图片 ≤9、话题 ≤3；文字与图片不能同时为空 |
| BR-05 | 可见范围 `public` / `followers`（仅关注我的人可见），默认 public |
| BR-06 | 帖子状态：`published`（默认）/ `hidden`（管理端下架，1.1）/ `deleted`（作者删除）；后两者对外返回 404 |
| BR-07 | 评论 ≤200 字，仅一层回复；删除后不可恢复 |
| BR-08 | 话题名 2–20 字，创建后不可改名 |
| BR-09 | 课程章节 1.0 全部解锁（`locked=false`） |
| BR-10 | 产品不出现价格与交易入口（价格位仅占位） |
| BR-11 | 资料校验：昵称 2–20 且非纯数字；生日 ≤ 今日且年龄 ≥12；城市选到市；简介 ≤30 |
| BR-12 | 身体档案：身高 100–250 整数；体重 30.0–200.0（1 位小数）；目标 1–3；部位 ≤6；旧伤 ≤100 |
| BR-13 | 完善度服务端计算，前端不得自行加减 |
| BR-14 | 收藏分 post/course/product/topic 四类，互不影响 |
| BR-15 | 搜索 ≥1 字、≤30 字，防抖 300ms，历史 ≤10 |
| BR-16 | 限流（服务端）：发布 5 次/时、评论 20 次/时、点赞 120 次/时、上传 30 次/时；超限 429 |
| BR-17 | 敏感词前置拦截（前端 + 服务端双重） |
| BR-18 | 删除操作一律二次确认（帖子/评论/退出登录） |
| BR-19 | Token 有效期 7 天；401 静默重登 1 次/请求 |
| BR-20 | 上传：仅 jpg/png/webp，单张 ≤5MB，头像裁 512×512 |
| BR-21 | 协议页必须可从 G01 与 M07 访问，内容由服务端下发或本地静态文本 |
| BR-22 | 分享仅 D05/C02/P02 三页可转发 |

### AC-01 登录与会话
1. 未勾选协议 → 只 Toast，无网络请求。
2. 勾选后登录成功 → 进入 D01，`jh_token` 写入，`GET /users/me` 成功。
3. 篡改 token 后任意请求 → 自动静默重登 → 原请求成功（用户无感）；re-login 也失败才跳 G01。
4. 冷启动无 token → 展示 M01，不弹任何授权框。
5. 退出登录 → M01，所有入口重新拦截。

### AC-02 社区
1. 首屏骨架 → 数据 → 无跳动；下拉刷新回到顶部。
2. 触底分页，`hasMore=false` 显示「没有更多了」。
3. 点赞乐观更新；断网时回滚 + Toast。
4. 关注后「关注流」出现该作者新内容（刷新后）。
5. 他人 `hidden` 帖子 → 「内容不存在或已删除」。

### AC-03 发布
1. 空内容「发布」禁用。
2. 500 字后无法输入，计数变红。
3. 第 10 张图 → Toast「最多上传 9 张图片」。
4. 话题选满 3 个 → 其余置灰。
5. 提交成功 → D09；返回 D01 刷新**能看到**自己的新帖（先发后审）。
6. 含敏感词 → 提交前拦截，不发请求。
7. 上传中断 → 已成功 URL 复用，草稿不丢。

### AC-04 课程 / 产品
1. 分类切换列表更新、滚动回顶。
2. 章节切换视频并高亮；退出页面停止播放。
3. 全屏 → Toast「1.0 暂不支持横屏」。
4. 产品详情无任何价格数字；图集 4 张指示器正确；参数长按复制。
5. 分享仅 3 个详情页可用。

### AC-05 我的与资料
1. 新用户 M02 完善度 `0/7` 或 `1/7`（微信头像）。
2. 填满 7 项 → `7/7`，完善度卡收起。
3. M03 未填为橙色；点击跳转并定位字段。
4. 昵称 1 字 → 保存被拦 + 红框；身高 300 → 范围提示。
5. 保存后 M02/M03 数据同步（store + 服务端）。
6. 协议页从 G01 与 M07 均可打开、可返回。

### AC-06 搜索与话题
1. 输入 1 字触发搜索，300ms 内连输不重复请求。
2. 无结果 → 空态文案。
3. 话题广场前三名色块正确；参与 → D07 预填。

### AC-07 生产化
1. `env=prod` 时 `USE_MOCK=false`，无 Mock 数据泄漏。
2. 断网 → 每页错误态 + 顶部黄条；恢复后重试成功。
3. 接口 5xx → Toast + `api_error` 上报带 `requestId`。
4. 主包 ≤2MB，总包 ≤20MB。
5. 冷启动到可交互 ≤1.5s（4G）。

## 10. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 首屏 ≤1.5s；页签切换 ≤100ms；列表 ≥55fps；图片懒加载 |
| 兼容 | iOS/Android 微信 8.0.40+；iPhone SE(375×667) 不破版；锁定竖屏 |
| 安全 | token 仅存本地；不打印 token/openid；上传校验类型与大小；HTTPS 全站 |
| 合规 | 协议与隐私页可访问；不收集身份证/病历；授权时机合规 |
| 可用 | 可点区域 ≥88×88rpx；对比度 ≥4.5:1；错误可恢复 |
| 可维护 | 令牌集中、组件复用、无硬编码色值；新增页面必须走 02 清单登记 |

## 11. 上线判据（Definition of Release）

1. 22 个业务页 + 1 个协议页在真实后端下全链路可用，Mock 关闭。
2. P0 用例 100% 通过（见 06 检查清单）。
3. 5 类异常（断网/空/401/429/上传失败）可复现且有兜底。
4. 提审四项合规通过：配置、域名、隐私、类目。
5. 主包体积、首屏耗时达标。
6. 后端 `/healthz` 正常、数据库迁移完成、备份已做。
